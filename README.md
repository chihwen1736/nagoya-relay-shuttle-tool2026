# 2026年第五屆名古屋亞帕運中繼站管理工具

這是一個**只有管理者會使用**的網頁小工具，用來把代表隊透過 LINE／Excel 提供的預約需求整理成正式的接駁班表。

**重要觀念**：這個工具**不是資料庫**，Excel 檔案才是正式資料。工具只是幫您「讀取 Excel → 整理顯示 → 自動排車 → 讓您調整 → 匯出 Excel」，資料只會暫存在您目前使用的這台電腦、這個瀏覽器裡，換一台電腦或清除瀏覽器資料，暫存的東西就會不見（所以請養成常常按「Excel 匯出」備份的習慣）。

與 `nagoya-relay-booking2026`（先前規劃的 Next.js／Supabase 版本，已保留為備份、暫停開發）以及 `nagoya-relay-map2026`（既有的據點查詢系統）完全獨立，不會互相修改或連動。

## 一、給管理者：怎麼使用這個工具（不需要懂程式）

### 1. 打開工具

用電腦（建議 Windows 版 **Chrome** 或 **Edge**）打開網址（部署完成後，網址會是 `https://<您的GitHub帳號>.github.io/nagoya-relay-shuttle-tool2026/`，實際網址由設定的人提供給您）。

打開時如果偵測到您之前有做到一半的工作，會跳出提示問您要不要「繼續上次工作」，選一個就可以了。

### 2. 準備 Excel 資料

- 第一次使用，建議先到「Excel 匯入」頁按「下載空白範本」，會拿到一份已經排好 6 張工作表、標題列都填好的空白 Excel（必填欄位標成淺黃色、日期/時間/代碼欄位已設定好格式、下拉選單欄位可以直接點選、首列凍結並開啟篩選，**沒有任何示範資料列**，直接照欄位填就可以）。
- 如果想先看看正確填法長什麼樣子，可以按「下載範例資料」，會拿到一份完整可直接匯入、驗證會全部通過的範例 Excel（示範單程派車、來回派車、同一預約單同時包含派車與治療防護、單獨餐食、單獨運動科學等常見情境）。**範例資料只供測試與參考格式使用，請勿直接拿來當作正式工作檔案**，正式作業請務必以空白範本另外建立。
- 這兩份檔案在本專案交付時也會直接附上一份實體檔案（`2026名古屋亞帕運中繼站管理系統_空白範本.xlsx`、`2026名古屋亞帕運中繼站管理系統_範例資料.xlsx`），內容與系統裡「下載空白範本」／「下載範例資料」兩個按鈕產生的檔案完全一致（兩者由同一份程式碼 `src/excel/styledWorkbook.ts` 產生，只有檔案內部的產生時間戳記不同）。
- 把代表隊透過 LINE／Excel 給您的資訊，整理填進空白範本。
- 6 張必要工作表：系統設定、隊伍資料、地點資料、車輛資料、車輛可用時段、預約資料。「接駁預排」是第 7 張，選填，只有在您想把之前的預排/調整成果一起帶回來繼續做時才需要。

### 3. 產生預約單編號

收到代表隊透過 LINE／Excel 傳來的預約需求後，可以到「Excel 匯入」頁的「預約單編號產生器」，選擇預約日期後按「產生編號」：

- 編號格式固定為 `RYYMMDD-XXX`，例如 2026-10-19 當天的第一張預約單編號會是 `R261019-001`。
- 系統會讀取您目前已匯入的預約資料，自動找出當天已使用的最大流水號，往下產生下一號；當天如果還沒有任何資料，就從 001 開始。
- 產生後按「複製編號」，把編號貼到 Excel 的「預約資料」工作表裡。
- 這個功能**只負責產生與複製編號**，不會建立網頁預約表單，也不會直接修改 Excel 或新增任何預約資料——Excel 仍然是唯一的正式資料來源。
- 同一張預約如果同時包含派車、治療防護等多項服務，請在 Excel 裡**分列填寫、但使用相同的預約單編號**；相同預約單編號搭配不同服務項目是允許的，但相同預約單編號＋相同服務項目重複出現，匯入時仍會被判定為錯誤，需要修正。
- 預約日期限定在系統設定的活動日期範圍內（開放起日～開放迄日），超出範圍會直接提示錯誤。

### 4. 匯入 Excel

回到「Excel 匯入」頁，選擇您整理好的檔案。系統會自動檢查：

- 有沒有錯誤（例如缺欄位、日期看不懂、隊伍代碼打錯、派車忘了填地點/時間/人數、來回忘了填回程時間…）——**只要有一項錯誤，整份都不會匯入**，畫面會列出每一項錯誤在哪張工作表、第幾列、哪個欄位，照著改就好。
- 有沒有警告（例如電話或備註空白）——警告不會擋住匯入，但建議之後補上。

驗證通過後：

- 如果這是您第一次匯入（畫面上原本沒有資料），會直接問您要不要匯入。
- 如果畫面上已經有資料了（您正在做前一輪的工作），會請您選：
  - **取代目前資料**：整個換成新檔案的內容（會提醒您先匯出備份）
  - **合併資料**：新的預約會加進來，內容一樣的自動略過，內容不一樣的（同一個預約單編號＋同一個服務項目，但欄位內容不同）會列出來讓您逐筆選「保留原本的」還是「用新的蓋掉」
  - **取消匯入**：不做任何改變

### 5. 看預約資料總表

匯入後可以到「預約資料總表」用日期／隊伍／服務項目／狀態篩選檢視所有預約，這頁純檢視，不能在這裡改資料。

### 6. 產生接駁行程預排

到「接駁行程預排」頁，選一個日期，按「預覽這次會取代的範圍」看看這次執行會動到哪些既有行程（**已經標記「已確認」的行程，以及您之前手動調整過的草稿，預設都不會被動到**），確認沒問題後按「執行預排」，系統會依照 45 分鐘一段、車輛座位、可用時段等規則自動排車，排不到車的會標示「未指派」。

如果您想整個重新排過（連同您之前手動調整過的草稿也一起重排，但已確認的行程還是不會動），勾選「全部重排」，系統會再跟您確認一次才會執行。

這一頁畫面寬度接近全螢幕，方便同時看到比較多欄位。

### 7. 人工調整

到「人工調整」頁選日期，就能看到當天所有車次（這一頁畫面也是接近全螢幕寬度，欄位較多時可以左右捲動，「車次／方向／出發時間」會固定在畫面左側方便對照）：

- 紅色底：未指派（沒有排到車）
- 黃色底：有衝突（座位不夠或跟同一輛車的其他行程時間重疊）
- 可以直接在表格裡改車輛、出發時間、上下車地點、人數、備註
- 可以「新增臨時車次」（例如加開一班沒有對應到系統預約的車）
- 可以「刪除車次」
- 調整完覺得沒問題，按「確認為正式」，這班車就會被標記成正式行程（匯出正式班表時只會抓「確認為正式」的車次）

### 8. 匯出 Excel

到「Excel 匯出」頁，可以匯出：

- **完整工作資料**：所有工作表都匯出，可以拿去重新匯入這個工具繼續做，也是最完整的備份
- **接駁班表**：選日期範圍，可以只匯出正式行程、或連草稿和未指派的一起匯出、或只匯出「未指派及衝突清單」方便您專門處理問題行程

### 9. 清除本機資料

如果要換一份全新的資料重新開始，可以在「Excel 匯出」頁最下面找到「清除本機資料」，會有二次確認，**清除前請務必先匯出備份**，清除後無法復原。

## 二、每日作業流程（建議操作順序）

給第一次接手這個工具、或想知道「每天到底要做哪些事」的管理者：

1. **範例資料只供測試**：`下載範例資料` 拿到的檔案是用來熟悉欄位填法與測試系統的，**不要**把它當成正式工作檔案繼續累積資料。
2. **建立正式資料**：第一次使用時，用「下載空白範本」建立您真正要用的正式 Excel，之後每天的異動都在這份檔案（或它的最新備份）上進行。
3. **收到預約先取號**：收到代表隊透過 LINE／Excel 傳來的預約需求後，先到「Excel 匯入」頁的「預約單編號產生器」取得當天的預約單編號，再把編號連同其他資訊填入正式 Excel 的「預約資料」工作表。同一張預約包含多項服務（例如派車＋治療防護）時，各服務分列填寫、共用同一個預約單編號。
4. **結單後執行預排**：到了每日結單時間（系統設定裡的「每日結單時間」，以日本時間 Asia/Tokyo 為準）之後，把整理好的 Excel 匯入系統，到「接駁行程預排」頁執行預排，再到「人工調整」頁確認每個車次沒問題後標記「確認為正式」，最後到「Excel 匯出」頁匯出正式接駁班表。
5. **完成後備份**：每次工作告一段落，都到「Excel 匯出」頁匯出一次「完整工作資料」，並以當天日期另存新檔（例如「中繼站資料_2026-10-19.xlsx」），養成習慣才不會因為換電腦、清除瀏覽器資料而遺失進度。
6. **多項服務同一編號**：無論是取號或事後檢查 Excel，都要記得同一張預約單如果包含派車、治療防護等多項服務，應該分成多列填寫、但全部使用同一個預約單編號；相同編號＋不同服務項目是正常的，相同編號＋相同服務項目重複出現則會在匯入時被判定為錯誤。

## 三、隱私與離線注意事項

- 這個工具是純前端網站，**沒有後端伺服器、沒有資料庫**，Excel 的解析、驗證、排車運算、匯出全部都在您的瀏覽器裡完成。
- 程式碼裡**沒有寫死任何真實的隊伍、車輛、聯絡人或預約資料**，這些都只存在您匯入的 Excel 與您瀏覽器的 IndexedDB 暫存裡。
- 沒有串接 Google Analytics 或任何追蹤服務，沒有引用需要連網下載的外部字型，Excel 讀寫用到的 SheetJS（一般資料匯出）與 ExcelJS（空白範本／範例資料的樣式化 Excel 產生）都是直接打包進網站檔案裡的，不是從外部 CDN 載入。
- 網站部署在 GitHub Pages，網址本身是公開的（任何人知道網址都可以打開空白的工具畫面），但因為所有資料只存在您自己瀏覽器的暫存裡，**別人打開這個網址不會看到您匯入的任何資料**。
- 因為沒有登入機制，請注意：如果您在公用電腦或共用瀏覽器上使用，暫存的資料理論上下一個使用同一台電腦、同一個瀏覽器的人也看得到（因為就存在那台電腦裡），建議在自己專用的電腦上操作，並記得定期清除。

## 四、給部署人員：怎麼把這個工具放上網（GitHub Pages）

### 1. 建立 GitHub Repo

在 GitHub 建立一個空的 repo，名稱建議用 `nagoya-relay-shuttle-tool2026`，然後：

```bash
cd nagoya-relay-shuttle-tool2026
git init
git add .
git commit -m "first version: excel import shuttle scheduling tool"
git branch -M main
git remote add origin https://github.com/<您的帳號>/nagoya-relay-shuttle-tool2026.git
git push -u origin main
```

### 2. 開啟 GitHub Pages

到 repo 的 Settings → Pages，Source 選擇「GitHub Actions」（不是選分支）。本專案已經內建 `.github/workflows/deploy.yml`，只要 push 到 `main` 分支，就會自動建置並部署，幾分鐘後網址就能打開。

### 3. 之後要更新網站

只要把改好的程式碼 push 到 `main` 分支，GitHub Actions 就會自動重新建置部署，不需要手動操作。如果是直接在 GitHub 網頁版覆蓋檔案（不用 git 指令），請參考本文件最後「這次更新需要覆蓋上傳的檔案」清單。

### 4. 本機開發（給要繼續改程式的人）

```bash
npm install
npm run dev
# 開啟 http://localhost:5173
```

`npm run build` 會先做型別檢查（`tsc --noEmit`）再打包，`vite.config.ts` 裡的 `base` 設定要跟您的 repo 名稱一致（`/repo名稱/`），如果改了 repo 名稱記得同步修改這裡。

### 5. 重新產生「空白範本」與「範例資料」兩份 Excel（給要維護欄位結構的人）

如果之後調整了 `src/excel/schema.ts`（例如新增欄位、改必填規則），空白範本與範例資料的內容需要跟著重新產生：

```bash
npm run generate:deliverables
```

會在專案根目錄產生 `2026名古屋亞帕運中繼站管理系統_空白範本.xlsx` 與 `2026名古屋亞帕運中繼站管理系統_範例資料.xlsx` 兩個檔案（用 `tsx` 直接執行 `scripts/generate-deliverables.mts`，呼叫的是跟系統內「下載空白範本」／「下載範例資料」按鈕完全相同的程式碼 `src/excel/styledWorkbook.ts`，確保兩邊永遠一致）。這兩個檔案不會被提交進版本控制（純產出物，需要時現場重新產生即可）。

## 五、Excel 工作表欄位對照表

| 工作表 | 欄位 |
|---|---|
| 系統設定 | 設定項目、設定值（開放起日／開放迄日／每日開始時間／每日結束時間／每日結單時間／單趟預估時間(分鐘)／系統名稱） |
| 隊伍資料 | 隊伍代碼、隊伍名稱、聯絡窗口、聯絡電話、備註、啟用 |
| 地點資料 | 地點代碼、地點名稱、地點類型（中繼站／住宿地點／比賽場館／其他）、地址、備註、啟用 |
| 車輛資料 | 車輛代碼、車輛名稱、座位數、備註、啟用 |
| 車輛可用時段 | 車輛代碼、日期、開始時間、結束時間、是否可用、備註 |
| 預約資料 | 預約單編號、隊伍代碼、預約日期、服務項目（派車／餐食／治療防護／運動科學）、開始時間、結束時間、人數、聯絡人、聯絡電話、上車地點代碼、下車地點代碼、單程或來回、回程時間、備註、狀態 |
| 接駁預排（選填） | 日期、車次、行程方向、車輛代碼、出發時間、上車地點代碼、下車地點代碼、搭乘人數、預約單編號、隊伍代碼、行程狀態、指派結果、產生方式、備註 |

**設計說明**：治療防護／運動科學的預約列，因為欄位表裡沒有另外規劃「服務地點」欄位，系統會借用「上車地點代碼」欄位當作服務地點代碼使用（「下車地點代碼」留空即可）。如果您希望改成獨立的服務地點欄位，之後可以再調整。

日期／時間欄位支援三種輸入方式：Excel 真正的日期/時間格式、Excel 日期序號、純文字（YYYY-MM-DD、HH:mm），系統會自動判斷並統一轉換，無法辨識的會列為錯誤，不會自行猜測。

「預約單編號產生器」產生的編號格式為 `RYYMMDD-XXX`（三位數流水號），此格式僅為建議格式，欄位本身仍是純文字，Excel 匯入驗證不會強制檢查編號格式，只會檢查「同一編號＋同一服務項目」是否重複。

## 六、目前完成的範圍與已知限制

**已完成**：Excel 匯入（含逐列詳細驗證報告，區分錯誤／警告）、取代／合併／取消三種匯入模式（合併會處理預約單編號＋服務項目的重複比對與衝突選擇）、預約單編號產生器（依日期自動找出當天最大流水號並產生下一號，只產生/複製編號、不寫回資料）、預約資料總表（含「已過結單時間」提醒，純顯示不鎖定）、接駁行程預排（來回拆去回程、45分鐘估算、座位/時段/衝突檢查、優先座位接近與趟次最少、預設保留已確認與人工調整過的草稿、全部重排需二次確認；此演算法本次未變動）、人工調整（改車輛/時間/地點/人數/備註、新增臨時車次、刪除車次、確認為正式）、多種 Excel 匯出情境、IndexedDB 本機暫存與「繼續上次工作」提示、清除本機資料、樣式化的「下載空白範本」／「下載範例資料」（必填淺黃色、下拉選單、凍結首列、自動篩選、日期/時間/代碼欄位格式、無示範資料殘留文字，由 ExcelJS 產生，系統內按鈕與交付附件用同一份程式碼）、「接駁行程預排」與「人工調整」兩頁採接近全螢幕寬度版面（最大寬度 1800px），人工調整表格較寬時可左右捲動並將車次/方向/出發時間固定在左側。已通過 `tsc --noEmit` 型別檢查與 `vite build` 正式建置，並用自動化瀏覽器測試（Playwright）實際跑過完整流程（詳見下方測試腳本）。

**已知限制／可以再加強的地方**：

## 七、自動化測試

`scripts/verify-e2e.mjs` 是端對端驗證腳本（不是專案正式測試套件），用 Playwright 對照實際建置後的網站逐項檢查，包含：空白範本／範例資料上傳辨識、接駁預排產生（含單程/來回行程正確性）、人工調整（改時間、改備註）、Excel 匯出（完整工作資料／正式接駁班表）、系統內下載按鈕與附件內容一致性。

`scripts/verify-layout-and-generator.mjs` 是本次新增版面寬度與預約單編號產生器的驗證腳本，檢查：「接駁行程預排」「人工調整」頁面主要內容區確實加寬、人工調整表格可左右捲動且維持最小寬度、預約單編號產生器能正確算出下一號（含「當日已有資料」與「當日尚無資料」兩種情境）、日期超出活動範圍會被擋下、複製編號按鈕可正常運作。

執行方式：

```bash
npm install -D playwright   # 只有跑這兩支測試腳本才需要，正式專案不依賴此套件
npm run build
npm run preview -- --port 4173 --strictPort   # 另開一個終端機視窗執行，保持執行中
node scripts/verify-e2e.mjs
node scripts/verify-layout-and-generator.mjs
```
